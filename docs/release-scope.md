# Release scope and identity

This is an independent export for `zhuconv/dbt-bench`; the active experiment workspace, its old runtime and sealed jobs were not reorganized. No git initialization, remote creation or push was performed. License selection is pending.

The supported replication entrypoint is `scripts/bench.py`, with `scripts/run_release_batch.py` retaining the reviewed finite native Harbor orchestration. `configs/local.toml` supplies deployment coordinates. The historical research scripts/checkers remain available for review, but workflows that reference full contracts, prior jobs or validation records require the exact external archive. They are not blanket-certified portable entrypoints.

The large historical `catalog/pools` and prepared/backend evidence are omitted; small candidate/family/version/legacy split declarations remain. Environment virtualenvs are omitted while recipes and lockfiles remain. Validation checker Python/source stays; full records, contracts with embedded evidence, large fixtures and ledgers are external. Runtime patch preimage/postimage content and the 515-file final package inventory are retained. Export source identities are separately indexed; old evidence hashes are not rewritten into new passing claims.

The current candidate population is 67 (15 ADE, 16 Spider, 36 DEB). 35 prepared 24h batch declarations cover 64 unstarted tasks; prior ADE pilots and repeat-purchase recovery are preserved outside that list. These declarations are not an authorization for simultaneous duplicate work: assign whole batches first. GPU validation of the active timeout runtime is a separate one-slot recovery. The export itself has not run a model request.

Known limits: no public image/evidence hosting has been selected; acquisition needs owner-approved shared storage. No cross-account result import/merge tool is implemented. `bench inspect` deliberately leaves audit/joint success unknown until qualified scoring and validity review of the captured submission. No split drawing/freezing or training operation is included in the release workflow.
